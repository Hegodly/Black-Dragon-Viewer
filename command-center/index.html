10 / Evidence boundary

What is proven vs. what is still unfinished

The categories below deliberately separate workflow evidence from behavior observed inside Second Life.

Proven in-world behavior

  • Only items marked PASS with a Windows viewer test record and evidence link.
  • Login, avatar, movement, rendering and PBR each need their own observed proof.
  • No behavior is pre-marked as proven by this dashboard.

Test-only / local-only

  • Compile, native tests, WARP / virtual GPU, unit tests and mock endpoints.
  • Local avatar, partial movement, preview scenes, synthetic assets and UI harnesses.
  • These validate components, not a live SL session.

Unfinished / missing backend

  • Any stubbed feature, placeholder UI, missing service, absent protocol or missing asset backend.
  • EventQueue/CAPS and UDP behavior without real session evidence.
  • Any subsystem not implemented in the actual Windows viewer.
11 / Non-negotiable direction

KAMI release requirements

Windows-only independent viewer

Standalone KAMI identity and real viewer executable; do not present the test program as the viewer.

Full DirectX 12 renderer

DX12 is the destination. Track the renderer migration by subsystem and prove real scene output.

Remove OpenGL

OpenGL must not remain as a hidden fallback in the final release path.

Remove Black Dragon remnants

Final packaging, UI, folder names, branding and resources must be KAMI-only.

FPS-conscious graphics

High-quality 1440p baseline, no FPS cap, measurable preset differences, PBR toggle and low-end scaling.

12 / Hardware matrix

Performance validation targets

Primary reference machine

RTX 5070 12GB · Ryzen 7 9800X3D · 32GB DDR5 · 1440p. Record average FPS, 1% lows, GPU/CPU utilization, VRAM and frame pacing.

Lower-end compatibility

Track integrated graphics and lower-tier discrete GPUs separately. Avoid requiring expensive features for basic login and world visibility.

Visual proof

Capture the same scene and camera for baseline / quality presets; note actual FPS and whether 4K/8K options visibly change output.
